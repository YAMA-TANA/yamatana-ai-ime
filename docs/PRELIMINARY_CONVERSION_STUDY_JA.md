# 実用変換パターン予備調査

## 結論

`だいごい → 第魚凍`はMozc辞書の問題ではない。AI IME 2.0.4が、Mozcでは`だい / ご / い`と分割される各セグメントを独立に並べ替え、語全体の意味を壊している。

AIを無効にしたMozcの先頭候補は次の通りだった。

```text
だい: 第
ご  : 五
い  : 位
結合: 第五位
```

したがって、単に「ご」の候補へ`5`を加点しても十分ではない。`第 + 5 + 位`を一つの仮説として評価する、複数セグメントの同時処理が必要である。

## 調査方法

Mozcの`converter_main`をローカルでビルドし、AIパイプを無効にした診断用バイナリから実際のセグメントと全候補列を取得した。その候補列へ現在のAI採点を適用し、CPU INT8とGPU FP16の両方で比較した。

評価セットは実務文、同音語、活用語、数詞、助数詞、日付、助詞の有無、複合語、短文脈、後続文脈、文脈なしを含む60ケースとした。数詞へ過剰適用しないことを確認するため、`一石二鳥`、`一期一会`、`第三者`、`二酸化炭素`など、漢数字のまま残す8ケースも含めた。

文脈条件は次の6種類で、各ケースについて候補順を通常・逆順の両方で試した。

- 前後文脈
- 前の文を含む前後文脈
- 前方だけ
- 後方だけ
- 短い前方文脈
- 文脈なし

## 候補列で判明した問題

### 候補を全部AIへ送ると遅く、精度も落ちる

52ケースの実候補列では、1セグメント当たりの候補数は中央値36、平均57.35、最大355だった。全候補を送る現方式では、CPUで10ケースが2秒を超えた。候補を先頭8件へ絞ると2秒超過は0件になり、前後文脈の正答も`30/52`から`37/52`へ改善した。

候補が多いほどよいわけではない。下位のノイズ候補がモデル比較と信頼度判定を不安定にしている。

### 同じ表記の重複が信頼度を壊す

60ケースの実候補列81セグメントには4,224候補があり、表記が同じ候補をまとめると3,211候補だった。1,013件、約24%が表記重複である。

現在の「1位と2位の点差」は同じ表記の重複候補同士を比較することがある。たとえば`ご`では`５`が複数存在し、実質的に同じ候補なのに点差0と判定され、正しい昇格を止める。信頼度は必ず異なる表記同士で計算する必要がある。

### 読み辞書ペナルティが数字候補を誤罰する

補助辞書には`いち → 1`や`さん → 3`がないため、Mozc自身が出した正当な数字候補へ未知語ペナルティ1.5が掛かる。一方、`ご → 5`は登録されており、読みごとに挙動が変わる。

Mozc候補であること自体を最低限の語彙根拠として扱い、数字・記号の正規化候補には外部辞書の未知語ペナルティを掛けない方が一貫する。

### 欲しい表記が候補外の場合もある

`じゅうにこ`は1セグメントになり、Mozc候補に`12個`が存在しなかった。この場合は並べ替えだけでは解決できない。安全に生成するには、読み全体を数詞として解析して`12`へ変換し、Mozc候補にある`個`と組み合わせる限定的な数詞コンポーザーが必要である。

## 文脈の実測

小さな統制候補群による60ケース、720判定では、GPUが`572/720`、CPUが`569/720`だった。GPUの文脈別結果は次の通り。

| 文脈 | 正答率 |
|---|---:|
| 前後 | 112/120 (93.3%) |
| 前の文を含む前後 | 112/120 (93.3%) |
| 前方のみ | 109/120 (90.8%) |
| 後方のみ | 94/120 (78.3%) |
| 短い前方 | 78/120 (65.0%) |
| なし | 67/120 (55.8%) |

前の別文を含めても結果が変わらないのは、現在の文境界切り出しが機能しているためである。前後文脈が最も安定し、前方のみがそれに続く。短文脈と文脈なしでは保守的にMozc先頭を維持すべきだが、読みの文字数だけでAI呼び出しを止める根拠にはならない。

## 数字表記の試験

候補を異なる表記で重複除去し、AIへ送る候補を先頭8表記に限定した上で、同値の算用数字候補を補充する実験を行った。全角数字と漢数字を比較用に正規化し、算用数字の表記加点を1.0、1.5、2.0で比較した。

| 加点 | 前後文脈 | 数字ケース | 漢数字維持 |
|---:|---:|---:|---:|
| 1.0 | 50/60 | 6/10 | 6/8 |
| 1.5 | 50/60 | 6/10 | 6/8 |
| 2.0 | 51/60 | 7/10 | 6/8 |

2.0がこの標本では最良で、`いちい → 1位`と`だいごい → 第5位`を選べた。ただし、独立セグメント処理のままでは`じゅうごにち → 105日`のような誤結合が起きる。したがって2.0は採用値ではなく、複数セグメント同時評価を実装した後に再校正する暫定値である。

CPUとGPUでも60件中3件の出力が異なった。閾値付近では実行プロバイダー差が出るため、異なる表記との点差が十分でない場合はMozc先頭を維持する必要がある。

### 句単位ビームとの組み合わせ

複数セグメントでは各セグメントの異なる上位2表記へ、同値の半角数字代表を1件補充し、その直積を句として一括採点した。1セグメントでは上位8表記による従来採点を使うハイブリッドを試した。

| 演算 | 前後 | 前方のみ | 後方のみ | 文脈なし | 2秒超過 |
|---|---:|---:|---:|---:|---:|
| GPU FP16 | 53/60 (88.3%) | 53/60 (88.3%) | 39/60 (65.0%) | 30/60 (50.0%) | 0 |
| CPU INT8 | 52/60 (86.7%) | 52/60 (86.7%) | 38/60 (63.3%) | 31/60 (51.7%) | 0 |

前後文脈では両方とも`だいごい → 第5位`と`いちい → 1位`に成功した。GPUではMozc先頭が正解だったケースを壊したのは`雨 → あめ`の1件、CPUでは0件だった。一方、CPU/GPU間では前後文脈でも`第2回`、`雨`、`非行少年`の3件が異なり、句単位化だけではプロバイダー差は消えない。

残る主な失敗は、Mozc候補に正解がない、または正しい数詞境界がない`12個`、`2026年`、`15日`と、固定表現の`一人一人`、ことわざ、`決裁`だった。これらは候補並べ替えではなく、数詞スパン構成、固定表現保護、辞書・境界修復の担当になる。

## 修正アルゴリズム案

### 1. 文字数による停止を廃止する

「1セグメント」「4文字または6文字」といった条件を「文脈なし単語」の代用にしない。1セグメントには短い単語だけでなく、`じゅうにこ`のような複合表現や、Mozcが一語として解析した長い句も含まれる。

代わりに次を使う。

- 文脈の有無と長さ
- 異なる表記候補間の点差
- 数詞・日付・割合・助数詞など、構造を検証できる候補群か
- Mozc先頭を含む語全体の仮説との点差

### 2. AI対象候補を前処理する

表示候補は削らず、AIで比較する代表候補だけを次の順で作る。

1. 表記で重複除去する。
2. Mozc上位8表記を採用する。
3. 上位8件と意味が同じ半角数字・記号表記が下位にあれば補充する。
4. 信頼度の2位は、1位と異なる表記の最高点を使う。

### 3. セグメント単位から句単位へ変える

隣接する2～4セグメントから、上位候補を組み合わせた小さなビームを作る。常にMozc先頭の全文を基準仮説として残し、各仮説を前後文脈込みで一度に採点する。

```text
読み:     だい / ご / い
基準:     第   / 五 / 位  = 第五位
候補:     第   / 5  / 位  = 第5位
ノイズ:   第   / 魚 / 凍  = 第魚凍
```

この単位なら「第5位」という全体意味で比較できる。採用後に、選んだ句を元のセグメントへ戻す。

### 4. 数詞スパンを先に構成する

連続する読みを数詞として解析し、数字部分を一度だけ正規化する。その後、序数・助数詞・日付・割合の接尾辞を結合する。

- `じゅうご + にち → 15日`。`10 + 5日 → 105日`にはしない。
- `にせんにじゅうろく + ねん → 2026年`。
- `だい + ご + い → 第5位`。
- `じゅうにこ → 12個`は、数詞`12`と助数詞`個`の両方を検証できた場合だけ生成する。
- `一期一会`や`第三者`は固定語・非数量用法として漢数字を維持する。

### 5. 時間予算を呼び出しごとではなく変換全体で管理する

現在の2秒という全体期限を維持するなら、候補8件と句ビームを一括推論する。左からでも右からでも、セグメントごとに多数候補を逐次推論すると後半または前半が期限切れになるだけである。

期限切れ時は、一部セグメントだけAI変換した混在結果を使わず、その句全体をMozc基準へ戻す。

## パラメータについての判断

## 非数詞・実務コーパスの追加調査

数字ケースへの偏りを避けるため、実Mozc候補を使う非数詞194ケースを追加した。97の意味場面それぞれについて「対象語だけ」と「助詞・活用込み」を対にし、日常同音語、異字同訓、営業・経理、IT、法務・行政、医療・科学、製造・物流を含めた。さらに、197セグメントになる60の長い実務句を別コーパスとした。

対象には`鼻/花`だけでなく、`雨/飴`、`紙/髪/神`、`橋/箸/端`、`決裁/決済`、`校正/構成/公正`、`精算/清算`、`施行/試行`、`規定/既定`、`補償/保証/保障`、`健診/検診`、および`会う/遭う/合う`、`直す/治す`、`測る/計る/量る/図る`などの活用形を含む。単語ごとの加点では片方を直すと反対例を壊す構成である。

助詞・活用を含めた194ケースもMozc上は全件1セグメントだった。したがって「助詞を含むから複数セグメント」とは仮定できず、セグメント数や読み文字数は文脈量の代用品にならない。一方、長句60ケースは2～5セグメントに分かれ、独立処理では一部分だけ`障害→傷害`、`旋盤→先番`のように変わる問題を再現した。

保存したCPU/GPUの全AIスコアから、固定点差、指数曲線、絶対AI素点、1文字当たり素点、softmax、エントロピー、シグモイド積、二次ロジスティックを比較した。前方のみ・後方のみを含む6文脈条件で、AI 1位とMozc 1位が競合した判断は1,024件である。

採用した方式は、候補全体のsoftmaxを使う方向制限付き非線形ゲートである。

- 通常はsoftmax 0.80以上。
- 外部文脈信号3文字以上、またはAI/Mozc候補の共通接頭・接尾が合計4文字以上でなければ変更しない。
- softmax 0.35以上かつMozc差1.80以上への緩和は、前後両側の文脈があるか、長い候補内部文脈がある場合だけ認める。
- 前方のみ・後方のみには緩和を適用しない。

この条件は1,024競合判断で286件を回復し、厳密一致上の改悪は7件だった。7件はすべて`見積もり/見積り`の表記差で、観測上の意味破壊は0件だった。CPUで194ケース×6条件を実装後に再推論した結果も、Mozc正答666件から767件へ増えた。回復104件、厳密表記差3件、意味破壊0件、時間切れ0件だった。

長い1セグメント句も止めない。候補2件で実測した`彼の顔の花は大きい → 彼の顔の鼻は大きい`は、GPU softmax 0.830・候補内部文脈8、CPUは0.880・8だった。`庭には美しい鼻 → 庭には美しい花`はGPU 0.991・6、CPU 0.969・6で、外部文脈がなくても採用できた。一方、短い文脈で生じた`輸送して → 油送して`は候補内部文脈3なので停止する。

本番へ反映したのは、候補代表数8、表記重複除去、および上記の方向制限付き非線形信頼度ゲートである。算用数字加点2.0と句単位ビームは上記の調査実装に留め、本番にはまだ入れていない。

既存のMozc順位減点0.22は、今回の標本では0に近い方が良い条件もあった。しかし、既存120問は「正解が必ずMozc 1位ではない」よう構成された回復試験で、誤上書き防止の校正には使えない。後述の前文脈ベンチは評価用として固定し、同じ210件へ過適合する形では0.22を変更しない。

## 人間入力を模した前文脈ベンチマーク

通常の左から右への入力を再現するため、後続文脈を一切与えず、前文脈だけを持つ105場面を作った。各場面は「対象語のみ」と「助詞・活用込み」の対なので合計210件である。日常、業務文書、IT、公共・医療、製造・物流、数値・固有表現を含み、`彼の顔の + はな`、`庭には美しい + はな`、`だいごい`、`なにがいちいになるのか`も直接含めた。実利用頻度による重み付けはしておらず、同音異義語を多めに置いた難問寄りの品質ベンチである。

表記を一つに強制するとIME品質を誤判定するため、指定表記の厳密一致と、人間にとって自然な表記揺れを認める実用正解を分けた。実用正解では`3時/三時`、`掛ける/かける`、`蜘蛛/クモ`などを同値とする一方、`鼻/花`、`決裁/決済`、`補償/保証`のように意味が変わる候補は同値にしていない。

CPU INT8、Mozc実候補、重複除去後の上位8表記、前文脈のみで再推論した結果は次のとおりだった。

| 段階 | 厳密一致 | 実用正解 |
|---|---:|---:|
| Mozc素順位 | 140/210 (66.7%) | 152/210 (72.4%) |
| AIモデルの生1位 | 199/210 (94.8%) | 206/210 (98.1%) |
| 安全ゲート＋補正後 | 199/210 (94.8%) | **210/210 (100.0%)** |
| AI上位2件に正解が存在 | - | 209/210 (99.5%) |
| AI上位3件に正解が存在 | - | 209/210 (99.5%) |
| 候補生成・送信の理論上限 | - | 210/210 (100.0%) |

最終版(v12)では、Mozcが正しかった152件を152件すべて保護し、Mozcが誤った58件を58件すべて回収した。回帰0件、タイムアウト0件で、実用正解は目標の95%(200/210)を10件上回った。`彼の顔の + はな → 鼻`、`庭には美しい + はな → 花`、`だいごい → 第五位`、`なにがいちいになるのか → 何が一位になるのか`も実用正解になった。

この改善はモデル再学習だけではなく、(1) AI1-Mozc1差、AI1-AI2 margin、Mozc順位、表記タイプを同時に見る安全ゲート、(2)同じ数値表現の`15日/十五日`を同値扱いする補正、(3)読みそのままの平仮名候補への条件付きペナルティ、(4)数詞・略語・`健診`の候補補完、(5)購入申請→決裁、法改正→規程などの実務フレーム補正、(6)複数セグメントへの公平な時間配分、による。候補生成不足はこのベンチで0件になった。
