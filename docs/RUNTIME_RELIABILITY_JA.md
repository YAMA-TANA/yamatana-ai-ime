# 実行時の応答性と復旧

## 再変換の推論を省略する

Named Pipeで動くONNX/Ruriバックエンドでは、同じ変換要求の検証済み結果を30秒間再利用する。最初の要求は即座に推論し、同じ入力に戻った場合に推論を省略する。初回変換の推論速度や、Mozc側の待ち時間上限を変更する機能ではない。

- キーは前後文脈、読み、推論トリガー、候補のID・表記・順位を含むSHA-256。要求ごとの`request_id`だけを除外する。
- 応答には常に今回の`request_id`を付ける。応答の変更が保存結果へ波及しないよう、キャッシュからは新しいリストを返す。
- 最大128件のLRU。1要求64候補を超える場合は保存せず通常の推論を行う。期限は計算完了から30秒で、再利用しても延長しない。期限切れの項目は次の要求で除去する。
- 例外、候補IDの欠落・重複、要求ID不一致、非有限スコアなどの不正応答は保存しない。既存のMozcフォールバック経路へ戻す。
- キャッシュは同じモデル・設定のプロセス内だけで使用する。トレイが設定変更を検知してモデルを再起動すると空になる。入力本文はキャッシュキーとして保持せず、ハッシュと候補ID・スコア・順位だけをメモリに保持する。キャッシュファイルは作らない。
- 旧Mozcクライアント向けの入力抑制処理の内側に配置し、入力中に返した暫定のMozc順位をAI計算済み結果として保存しない。

既存のローカル状態ファイルには`cache_hits`と`cache_misses`の件数を追加する。後者はキャッシュを使わずバックエンドを呼んだ回数で、失敗も含む。本文・候補表記・ハッシュは状態ファイルへ追加しない。

## 自動GPU選択の復旧

DirectMLプロバイダーが列挙されていても、ドライバーやモデルの実行が成功するとは限らない。自動選択では、GPUモデルの解決、セッション作成、ウォームアップ、実際に有効なプロバイダーの確認までを起動判定に含める。

GPU起動に失敗した場合はセッションを破棄し、CPU専用の新しいセッション設定とCPU用モデル（INT8優先、従来のFP32代替を維持）で一度だけ再試行する。CPU起動にも失敗した場合は既存のエラー処理に戻り、Mozc変換を維持する。「GPU」明示指定ではCPUへ無言で切り替えず、失敗を知らせる。「CPU」指定ではGPUを試さない。

使用モデルと同じフォルダの`tokenizer.json`を優先する。開発用の`model_path`を明示した場合はCPU再試行でもそのモデルを維持し、別モデルの評価結果が混ざるのを防ぐ。

この復旧は起動時のもの。起動後のGPU故障は既存の要求単位の失敗処理で扱う。採点式、信頼度しきい値、モデル重み、候補数、Mozc側の文節処理は変更していない。

## 検証

`tests/test_ranker_cache.py`で、再利用、要求ID更新、各入力フィールドの変更、期限切れ、LRU追い出し、容量超過、不正応答、旧クライアントの入力抑制、実際のサーバー起動経路への組み込みを検証する。

`tests/test_onnx_startup.py`ではONNXセッションをテスト用に置き換え、GPU作成失敗、ウォームアップ失敗、プロバイダー脱落、GPUモデル欠落からのCPU復旧と、CPU/GPU明示指定の扱いを検証する。実GPUドライバーの互換性や実モデルの変換精度・遅延を測定する試験ではない。
